# MSC2545 帳號數據貼圖包 / Sticker packs in account data

> 日期 / Date:2026-08-31。配套腳本:`scripts/msc2545_sync.py`(寫入)、
> `scripts/holes.py`(缺洞檢測)、`scripts/verify_against_telegram.py`(Telegram 實時對帳)。

## 格式決策

「MSC2545 貼圖包寫入帳號數據」採用**原始草案(2020,Sorunome)定義、並被
Nheko / Cinny / FluffyChat 實際支援**的 user-pack 帳號數據格式:

- 每個包一條帳號數據事件:`im.packs.user.<telegram_short_name>`
- 一條全域清單事件:`im.packs.global`,內容 `{"packs":[{"type":"users","id":"@自己"}]}`

包內容結構(由 `web/packs/<short>.json` 轉換,媒體 mxc 直接復用,零上傳):

```json
{
  "pack": {"display_name": "包標題", "avatar_url": "mxc://…(首張)"},
  "images": {
    "<telegram_document_id>": {
      "url": "mxc://…",
      "body": "alt/表情文字",
      "info": {"mimetype": "image/png", "w": 256, "h": 256, "size": 123456}
    }
  }
}
```

注意:2026-05 起 matrix-spec-proposals main 上的 2545 文本已被改寫為
`m.room.image_pack`(房間 state)+ `m.image_pack.rooms`(帳號數據指向房間)的新方案,
**沒有** user account data pack 概念,且需另行建房間;故本專案不用該命名。
日後若需要,可在既有基礎上另寫一個「建房間 + state 事件」的轉換器。

## 行為要點

- **冪等**:每包 payload 的 sha256 記在 `scripts/msc2545-state.json`(gitignored),
  內容沒變就不 PUT;本地刪掉的包會對應 DELETE 遠端事件。
- `im.packs.global` 為讀-改-寫:保留第三方 user pack,只確保含本帳號條目。
- 0 張的空包不發佈;`net.maunium.telegram.*` 不寫入(體積),圖片 key 即 TG doc id,反查已足夠。
- payload 全部緊湊序列化,現有最大 29 KB(遠低於一般伺服器 64 KB 事件上限)。
- token 失效(`M_UNKNOWN_TOKEN`)→ exit 2 並印 `TOKEN_DEAD`,更新 `config.json` 後重跑即可。
- `--dry-run` 只構建 payload 不碰網路;`--force` 全量重寫。

## 已知數據特殊性(2026-08-31)

- 13 個本地包(`ArcaeaLinkPlay`、`CacheCI`、`kirinfav_by_favorite_stickers_bot` 等)是
  另一工具以 `sha256:<hash>` 為 id 產生的,無 Telegram metadata:其中 8 個包已從
  Telegram 帳號移除(本地照常發佈),其餘的會在補洞重跑時被 sticker-import 以
  tg doc id 全量重傳取代,隨後本腳本會自動重新同步。
- 3 個空包(`MygoStickerByAsahiRise`、`USABest`、`kawaiikipfel_by_moe_sticker_bot`)
  待補洞完成後自然納入。

  `scripts/holes.py` 輸出;補洞由每小時排程(配額雙閘)自動消化。
